# RTL 实现参考 (RTL Implementation Guide)

> 本文件汇总外部数字逻辑编码规范（Verilog RTL 编码规则与逻辑军规 J1–J8）中**对设计质量有直接帮助**的内容，作为 rtl-flow 的实现参考。
> 阅读对象：`architect`（分解与选型）、`rtl-engineer`（编码与自检）。`debugger` 判断「RTL 是否违反规则导致行为错误」时可参考 §9.4。
>
> **本文件不是规范本体，也不被任何脚本自动检查。** 唯一可自动检查、必须严格遵守的是 [`rtl-coding-style.md`](rtl-coding-style.md) 的 `RTL-xx` 规则；本文件的 `DG-xx` 是补充设计质量要求，冲突时以 `RTL-xx`、SSOT（`data/<ip>.yaml`）和原始命名为准（差异清单见 §10）。
>
> 情态词：`必须`（强制，偏离须在 `05_rtl_structure.md` §6 写明原因，重要取舍记 DEC）/ `应`（推荐，偏离需在 05 §6 说明）/ `宜`（建议，无需记录）。

## 1. 军规 J1–J8 与 rtl-flow 规则的对应

| 军规 | 要求 | rtl-flow 落点 | 检查 |
|---|---|---|---|
| J1 | 每个 `always` 块只驱动一个信号 | `RTL-53`（一个 `reg` 只在一个 `always` 块赋值；同块不混合时序与组合） | lint / 评审 |
| J2 | 所有信号显式声明，禁止隐式声明 | `RTL-01`（禁止 SystemVerilog 隐式类型）+ `DG-20` | 评审 |
| J3 | 常量必须带位宽 | `RTL-55`（`1'b0`、`8'hFF`、`{W{1'b0}}`，禁止魔数） | lint |
| J4 | 禁止锁存器推断 | `RTL-52`（组合块首行赋默认值或全分支赋值） | 综合 / 评审 |
| J5 | 禁止组合环 | `RTL-57` | lint |
| J6 | 跨时钟域必须同步 | `rtl-coding-style.md` §9（两级同步器 / 握手 / 异步 FIFO，CDC 表） | 评审 + CDC 工具 |
| J7 | 模块输出必须寄存打拍 | `RTL-33`（协议要求组合输出时在 05 §6 说明） | 评审 |
| J8 | 单模块有效代码 ≤ 2000 行 | `RTL-09`（普通模块 300–1000 行，更严） | 评审 |

J1–J8 已全部被 rtl-flow 覆盖；下表是 rtl-flow 规范**没有展开**、但对生成质量影响最大的部分。

## 2. 设计分解与模块划分 (DG-1x)

| 编号 | 规则 |
|---|---|
| DG-10 | **必须**从全局考虑实现：综合、DFT、P&R、时序收敛与后续集成；不为局部代码简短而牺牲可测性。 |
| DG-11 | **应**按功能内聚、模块间松耦合分解。RTL 不是软件，一个模块一个文件，**不宜过碎**；能内聚在一个模块的逻辑不要拆成三个只含几行的模块（与 `RTL-09` 的 300 行下限一致）。 |
| DG-12 | **应**按功能 / 时钟域 / 接口边界划分：一个模块尽量只用一个时钟、只属于一个时钟域（同 `RTL-40`）；时序紧张的相关逻辑放在同一模块，便于单独加约束。 |
| DG-13 | **必须**把时钟产生电路、复位产生电路单独成模块；设计中确实存在的异步逻辑单独成模块并尽量局限在少数模块内。 |
| DG-14 | **必须**避免串通信号：模块输入不经任何逻辑直接输出到模块外部。需要透传时由上层连接，不在模块内部开直通路径。 |
| DG-15 | **应**避免 snake path（信号从 A 输出，穿过 B、C 又回到 A）；这类路径综合时难以约束。反复用到的条件组合抽成公共信号（见 DG-25）。 |
| DG-16 | **应**将可共享的组合逻辑放在同一模块，便于综合工具资源共享；相互交互逻辑的时钟尽量晚分叉，减少 OCV 影响。 |
| DG-17 | **应**保证时钟、复位从同一路径进入模块；大模块接口设计要考虑后端时序收敛困难时接口信号可被 pipeline。 |
| DG-18 | **宜**控制设计层次在 6 层以内；例化层次的模块内不写 glue logic（数据改名、位选、拼接除外）。 |
| DG-19 | **必须**避免重复代码：相同功能抽成基础重用模块（`RTL-08`，有效代码 < 500 行），避免多处修改。 |

分解结果写入 `02_architecture.md` §2 子模块表；`rtl-engineer` 按表实现，不自行增删模块。

## 3. 编码细则补充 (DG-2x)

| 编号 | 规则 |
|---|---|
| DG-20 | **必须**显式声明所有 `wire` / `reg`，不使用隐式声明；声明区集中放在模块前部（先 `reg` 后 `wire`），端口声明与内部信号声明分开。 |
| DG-21 | **必须**每行一条语句、4 空格缩进、不用 Tab；`begin` 与 `if` / `else` / `always` 同行，`end` 单独一行并与其语句对齐（同 `rtl-coding-style.md` §8）。 |
| DG-22 | **必须**不在定义 `wire` 时赋值（`wire x = y;` 禁止），写作声明 + `assign`。 |
| DG-23 | **必须**加一 / 减一写作 `+ WIDTH'd1` / `- WIDTH'd1`；赋值与比较两侧位宽一致（`RTL-55`）。 |
| DG-24 | **必须**不在条件表达式中使用 `+`、`-`、`<<` 等运算符（如 `if ((a + b) > c)` 禁止）；先算到中间信号再比较。 |
| DG-25 | **必须**把重复出现的立即数 / 常数抽成 `parameter` / `localparam`，重复出现的多信号条件组合抽成公共信号；不得在多处写同一魔数（`RTL-55`）。 |
| DG-26 | **应**避免过长或嵌套过深的条件表达式；用括号明确优先级，不依赖运算符默认优先级；`if` 嵌套超过 4 层改写为 `case`（`RTL-56`）。 |
| DG-27 | **应**用 `case` 实现非优先级选择器；优先级译码用 `if / else if`（`RTL-54`）。条件项 ≤ 5 时两者面积相当，> 5 时 `case` 更省面积。 |
| DG-28 | **必须**为组合 `case` 写 `default`、为组合 `if` 写 `else` 或首行赋默认值（`RTL-52`）；`default` 取固定逻辑值，不取高阻。 |
| DG-29 | **应**让多路选择器的输入状态数尽量为 2^n，`case` 起始状态取 0；未用编码并入 `default`。 |
| DG-30 | **必须**循环次数为常数（`for` 的上界必须是参数或常数），否则不可综合。 |
| DG-31 | **必须**使用 `generate` / `for` 时定义块名（进程名），以便区分同一模块中的多个循环体并支持同名循环变量。 |
| DG-32 | **必须**单独 `for` 结构中的位选使用增量下标 `sel[2*i +: 2]`，不写 `sel[2*i+1 : 2*i]`。 |
| DG-33 | **应**把复杂组合逻辑写在 `always @(*)`，简单改名 / 拼接 / 位选用 `assign`。 |
| DG-34 | **必须**保持 `always @(*)` 敏感列表为 `*`，不手写不完全的电平列表（`RTL-51`）。 |
| DG-35 | **宜**使用二维数组与变量索引简化结构规整的逻辑，索引寻址范围取 2^n。 |
| DG-36 | **必须**在条件表达式中不使用 `z`，尽量避免 `x`（`RTL-62`）。 |

## 4. 时钟、复位与 CDC (DG-3x)

| 编号 | 规则 |
|---|---|
| DG-40 | **必须**保证时序块只有一个时钟、只在一个沿动作（`RTL-40`）；一个功能模块通常只使用一个时钟沿。 |
| DG-41 | **必须**保证异步复位（或置位）二选一，且复位信号不插入组合逻辑，避免毛刺（`RTL-41`、`RTL-42`）。 |
| DG-42 | **必须**不把时钟用作数据、不作为组合逻辑的输入或输出；不在模块内用组合逻辑产生时钟或门控时钟（分频用使能代替）。「时钟 / 异步复位必须直接来自本模块 input 端口」已由 `RTL-43` / `RTL-44` **自动检查**（如 `assign cs_clock = !cs_n;` 后 `posedge cs_clock` 会报 error）。 |
| DG-43 | **必须**让所有时钟与异步复位在顶层可控、可观测（顶层独立端口，`RTL-44`）；芯片顶层不从输出信号回读。 |
| DG-44 | **必须**让跨时钟域信号先成为源时钟域的寄存器输出，再进入同步器；单 bit 用两级（以上）同步器，脉冲先展宽再同步后取沿；多 bit 用握手 / 异步 FIFO / 格雷码，禁止直接两级同步多 bit 总线。 |
| DG-45 | **必须**按 `rtl-coding-style.md` §9 列出全部 CDC 路径；同步后的信号在本规范中不加固定后缀，同步关系写在 02 的 CDC 表中。 |

## 5. FSM (DG-4x)

| 编号 | 规则 |
|---|---|
| DG-50 | **必须**采用三段式（状态寄存、次态组合、输出寄存），组合与时序分离（`rtl-coding-style.md` §7）。 |
| DG-51 | **必须**用 `localparam` 定义状态编码（`RTL-21`），不手写魔数；状态名与 02 状态转移表一一对应。 |
| DG-52 | **必须**用 `case` 描述状态转移并写 `default`，`default` 回到安全状态（通常为 `ST_IDLE`）。 |
| DG-53 | **应**为频繁切换的相邻状态选格雷码，保证单比特翻转；小型状态机可用 one-hot / one-cold。 |
| DG-54 | **应**避免冗余状态与频繁大比特翻转的状态迁移；状态编码使用最少比特。 |

## 6. RAM / Memory (DG-5x)

| 编号 | 规则 |
|---|---|
| DG-55 | **必须**保证 RAM 读写地址不溢出，尤其深度非 2^n 时；双口 RAM 读写不得冲突，同一地址同拍读写的行为必须在 02 中明确并覆盖测试点。 |
| DG-56 | **应**优先单口 RAM；双口 RAM 要慎重，双口需同时读写的场景即便比特数小也不要用寄存器搭建。 |
| DG-57 | **应**让 RAM 的地址、控制与输出数据均为寄存器输出；读出数据需要连续多拍使用时先寄存，并在注释中说明读出延迟拍数。 |
| DG-58 | **应**减少 RAM 块数、归并尺寸相近的 RAM；比特数很小的 RAM（参考量级：双口 < 1024 bit 或单口 < 16×32 bit）直接用寄存器搭建。 |
| DG-59 | **必须**把 RAM 单独封装，模块名反映深度、位宽与端口类型（如 `ram512x8s`、`ram512x8d_1w2r`）；同一文件内用宏区分 ASIC RAM / FPGA RAM / 行为模型。02 中给出 Memory 选型（容量、单双口、端口数、时钟域），04 中说明与寄存器实现的边界。 |

## 7. DataPath (DG-6x)

| 编号 | 规则 |
|---|---|
| DG-60 | **必须**用 `$signed` / `$unsigned` 明确有符号语义，有符号与无符号不得混合运算。 |
| DG-61 | **必须**不对有符号数做位选或拼接（位选 / 拼接结果总是无符号）；需要在同一链路切换有无符号时，用 0 扩展 / 符号位选择实现。 |
| DG-62 | **必须**用算术符号 `-` 求负数补码，不手写「按位取反加 1」。 |
| DG-63 | **应**把运算逻辑拆分到最小单元，明确每一步位宽，用中间信号承载，保证算术表达式位宽正确。 |
| DG-64 | **应**把相关的一组数据通道合并为单一组合块，便于综合提取 DataPath；不提倡例化 DesignWare 运算单元，直接用算术表达式。 |
| DG-65 | **应**在满足时序的前提下复用运算单元、采用时分复用或串行处理，减小面积。 |

## 8. 低功耗与成本 (DG-7x)

| 编号 | 规则 |
|---|---|
| DG-70 | **必须**便于综合工具自动插入时钟门控：使能型寄存器写成 `if (en) q <= d; else q <= q;`，而不是依赖手工外部门控。 |
| DG-71 | **必须**让时钟门控不超过两级；模块级门控按功能划分关断空闲模块。 |
| DG-72 | **应**让「无关项」保持原值而非强制清 0，减少无谓翻转；降低高翻转率信号的逻辑深度。 |
| DG-73 | **应**对 RAM 的时钟、片选与地址做门控，深度为 2^n 且地址规律递增 / 递减时可用格雷码编码地址以减少翻转。 |
| DG-74 | **宜**采用操作数隔离：不运算时保持运算单元输入不变，避免输出翻转；复杂运算可用超前计算。 |
| DG-75 | **应**在设计时能估算资源占用（选择器、比较器、运算单元数量与位宽），并在 02 的面积估计中给出依据。 |
| DG-76 | **应**优先树状结构实现优先级编码器；链状面积占优、树状速度占优，按 02 的面积 / 时序目标选择。 |

## 9. 注释、可读性与交付 (DG-8x / DG-9x)

### 9.1 注释

| 编号 | 规则 |
|---|---|
| DG-80 | **必须**用 `//` 行注释；文件头与文件尾按 `rtl-coding-style.md` §8（`RTL-04` 自动检查），不在 RTL 中另写版权 / 联系人字段。 |
| DG-81 | **应**在模块功能代码前用一段注释说明总体工作步骤、结构（可引用 02 的框图与 §2 子模块表）和关键数据结构。 |
| DG-82 | **应**在每个功能块逻辑前说明该段的功能；对晦涩代码、复杂时序（如 RAM 读出延迟、多拍握手）给出说明。 |
| DG-83 | **必须**在声明处逐信号行尾注释（含义、来源 / 去向、位宽）；关键代码行行尾注释垂直对齐。ANSI 端口列表内的端口不重复注释，注释写在声明区或就近说明。 |
| DG-84 | **必须**删除无用旧代码而不是注释掉；注释与代码不同步时以代码为准并立即修正注释。 |
| DG-85 | **必须**在注释与 05 中引用 `REQ-xxx` / `DEC-xxx` / `ITR-xxx`，保持可追溯。 |

### 9.2 生成前检查清单（rtl-engineer 动笔前）

- [ ] 已读 01 / 02 / 03 / 04 / `data/<ip>.yaml`，模块清单与 02 §2 一致，无自增模块
- [ ] 端口名、方向、位宽、顺序与 yaml 完全一致；`rtl_files` 已按 02 更新（`define.v` 第一、顶层第二）
- [ ] 输入中已有的所有名称原样复用，未改名、未加前后缀
- [ ] 每个模块的时钟域、复位极性、复位值已确认（内部复位极性由 `define.v` 决定）
- [ ] FSM 的状态集合与转移条件来自 02 状态转移表；状态编码用 `localparam`
- [ ] CDC 路径已列入 02 CDC 表；RAM 选型与容量已在 02 说明
- [ ] 参数与常量已参数化，无重复魔数

### 9.3 生成后自检清单（提交 lint 前）

- [ ] `python $SKILL/scripts/check_style.py <ip_dir>` 0 违规（`RTL-xx`）
- [ ] 每个 `always` 块只驱动一个信号；组合块无锁存、有 `default` / 默认赋值；无组合环
- [ ] 所有信号显式声明；`wire` 不在声明处赋值；敏感列表用 `*`
- [ ] 赋值两侧位宽一致，常量带位宽，加减 1 写作 `WIDTH'd1`
- [ ] 时序块单一沿、非阻塞 `<= #`U_DLY`；复位比较用 `==`，复位不插组合逻辑
- [ ] 无内部产生时钟、无三态、无 `initial` / `#` 延时 / 系统任务
- [ ] 三段式 FSM，`case` 有 `default` 且回安全态
- [ ] 跨时钟域信号均经同步器 / 握手 / 异步 FIFO，且为源域寄存器输出
- [ ] 关键寄存器 `if (en) ... else 保持不变`，便于自动门控
- [ ] 文件头字段齐全，声明处逐信号注释，注释引用 REQ / DEC
- [ ] `python $SKILL/scripts/run_lint.py <ip_dir>` 零 error；warning 修复或在 05 §7 豁免
- [ ] 违反 `DG-xx` 的条目写入 05 §6（位置 / 规则 / 偏离内容 / 原因 / DEC）

### 9.4 失败反馈闭环

| 现象 | 处理 |
|---|---|
| `check_style.py` / `run_lint.py` 报 `RTL-xx` | 按规则修 RTL，不改命名、不改规格；确实需要偏离时写 05 §6 并记 DEC |
| lint 报 warning | 优先修复；保留时写 05 §7（工具 / 规则 / 位置 / 原因） |
| 回归失败 | 不改 RTL 自行试错；由编排者派 `debugger` 定位，按报告修复并在 ITR 补写「修改」 |
| 认为规格有问题 | `status: blocked`，写 `blocked_reason`，交回编排者与用户决定 |
| 工具 / 环境错误（license、远程不可用） | 属环境问题，`status: blocked` 并附上报错，不为环境问题改设计 |

`debugger` 可对照本文件 §2–§7 判断「RTL 是否违反设计规则导致行为错误」，但根因判定仍以规格为准。

### 9.5 交付物

- 不创建 `compile_<模块>_<日期>/` 之类的临时编译目录，不生成 `*_optimized_*.v` 副本：报告统一为 `reports/lint.log` 与 `reports/regress.json`，改动记录在 `doc/08_iteration_log.md`。
- 模块清单、层次、参数、偏离与豁免写入 `doc/05_rtl_structure.md`；`check_docs.py --stage rtl` 必须无 ERROR。

## 10. 与外部规范的已知差异（不要照搬）

| 外部规范做法 | rtl-flow 做法 | 依据 |
|---|---|---|
| 用 iverilog 编译并生成独立编译报告目录 | 用 `check_style.py` / `run_lint.py`（远程 SpyGlass 或 VCS），报告写 `reports/lint.log` | `SKILL.md` §6、`rtl-coding-style.md` §11 |
| 编译失败生成 `<文件>_optimized_YYYYMMDD.v` 副本，不改原文件 | 直接修改 `rtl/` 原文件，改动记 ITR；不产生副本 | 单一信息源、可追溯 |
| 文件头含 Copyright / Project / Author / Email / Called by | `RTL-04` 规定的文件头字段 | `RTL-04` 自动检查 |
| 文件尾写 `Modification History` 修订块 | 版本历史写 `CHANGELOG.md` 与 `doc/08_iteration_log.md`，RTL 文件不写文件尾 | 单一追溯点 |
| 在 RTL 中直接写断言 / cover（「断言是注释的良好方法」） | RTL 保持 Verilog-2001、不写 SVA；协议与不变式检查放 monitor 或 TB interface，列入 07 §4 | `RTL-60`、`RTL-61`、`rtl-coding-style.md` §10 |
| 禁止单位延迟 `#1`，复位 / 赋值不带延时 | `` <= #`U_DLY `` 是仅供仿真的宏延时（综合忽略），其余 `#` 延时仍禁止 | `RTL-50`、`RTL-60` |
| 名字长度限制：模块 3~25 字符、信号 ≤ 32 字符 | 输入给出的原名不因长度改名；长度只约束未命名的新对象 | `RTL-10`、`RTL-12`、`RTL-17` |
| 强制 `clk_` / `rst_` 前缀、`_n` / `_z` 后缀、`U_` 例化名、禁 `_reg` 后缀等命名规则 | 输入已给出的名称原样保留（`RTL-10`~`RTL-22`）；这些风格只用于**未命名的新对象** | 原始命名优先 |
| 每行建议 ≤ 72 字符 | ≤ 100 字符 | `rtl-coding-style.md` §8 |
| 模块 1000–2000 行 | 基础模块 < 500 行，普通模块 300–1000 行，包封模块不受限 | `RTL-08`、`RTL-09`、`RTL-35`~`RTL-39` |
| 状态编码用 `parameter` | 用 `localparam` | `RTL-21` |
| `casex` 用 x 匹配无关项 | 禁用 `casex`，允许 `casez` | `RTL-54` |
| 异步复位固定低有效、写 `if (rst_n == 1'b0)` | 内部复位极性由 `define.v` 的 `RST_EDGE` / `RST_ACT` 统一；标准接口复位按 yaml 的 `active` | `RTL-41`、`RTL-42` |
| 时序赋值写 `<=` | 写 `` <= #`U_DLY `` | `RTL-50` |
| 允许内部子模块使用三态（仅建议避免） | IP 内部禁止三态，三态只在芯片顶层 | `RTL-34`（自动） |
| 除时钟 / 复位产生模块外避免例化工艺门单元 | 同样建议避免（保证工艺无关）；`RTL-65` 只自动拦截开关级原语，门单元例化由评审把关，确需时在 05 §6 说明 | `RTL-65`、DG-10 |
