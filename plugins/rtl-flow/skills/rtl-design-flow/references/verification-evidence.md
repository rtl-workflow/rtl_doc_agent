# 可选验证证据合同（v1）

本功能在现有 TEST/UVM 生命周期、退出码、COVER 和 G3 审核基础上，增加可执行的活动要求、明确种子计划和独立运行记录。它不替代参考模型、协议检查或真实仿真；日志中的计数仍需由经过审核的验证组件产生。

## 启用与兼容

在 IP 目录添加 `dv/evidence.json`。没有此文件时保留原来的执行和判定规则。启用后适用于 UVM 和已有原生 Verilog TB，仍使用 `run_regress.py`，不引入另一套执行器。`dv/uvm.yaml` 的格式与 VCS UVM 版本选择不变。

示例（测试名必须替换为 07 中实际“仿真”用例全集）：

```json
{
  "schema_version": 1,
  "tests": {
    "tc_smoke": {
      "seeds": [1, 7],
      "minimum": {
        "observations": 1,
        "checks": 1,
        "expected": 1,
        "actual": 1,
        "comparisons": 1
      },
      "zero": ["mismatches", "outstanding"],
      "equal": [["expected", "actual", "comparisons"]]
    }
  }
}
```

- `schema_version` 为整数 1；未知字段、错误类型和不完整配置报错，不悄悄回退。
- `tests` 必须与 `doc/07_dv_plan.md` 中解析出的仿真用例一一对应，不遗漏、不增加未登记测试。
- 每个测试的 `seeds`、`minimum`、`zero`、`equal` 都必填。种子为正整数、不可重复，布尔值不是整数种子。
- `minimum` 至少包含 `observations` 和 `checks`，两者阈值至少为 1；其他最小值为非负整数。`zero` 至少包含 `mismatches` 与 `outstanding`。
- `equal` 是计数名称组的列表；每组至少两个不同名称，要求其实际值相等。不需要额外相等关系时填空数组。
- 计数名称使用字母开头的字母、数字和下划线；JSON 中不得使用重复键。

显式种子计划替代启用模式下原来的测试名包含 `random` 才展开种子的规则，`--seeds` 不扩展或缩减合同中的种子集合。`--test tc_smoke` 只选该用例并执行其声明种子；局部运行不能替换完整回归报告。

## 指标来源和输出

每个 test/seed 必须输出每项声明计数且仅一次，独占一行：

```text
RTL_FLOW_METRIC observations=8
RTL_FLOW_METRIC checks=8
RTL_FLOW_METRIC expected=8
RTL_FLOW_METRIC actual=8
RTL_FLOW_METRIC comparisons=8
RTL_FLOW_METRIC mismatches=0
RTL_FLOW_METRIC outstanding=0
```

声明计数是 `minimum`、`zero` 和 `equal` 中名称的并集。缺少、重复、格式错误、负数或未声明计数均失败。现有 TEST、UVM 开始/完成、错误统计和 COVER 输出仍需保留；新指标不允许掩盖它们的失败。

在 07 中说明各计数的生产组件、采样事件和递增条件：

- `observations` 来自 monitor 的真实接口观察，不能用 driver 计划发送次数冒充。
- `checks` 来自实际执行的功能或协议判定，不是调用空 checker 的次数。
- `mismatches` 汇总失败的判定；`outstanding` 表示结束时仍未结算的检查/事务。
- 数据场景可按示例核对 expected/actual/comparisons。拒绝、复位、无数据完成等场景应定义其有效观测和检查，不为了符合数据比较公式伪造 accepted 或 comparisons。
- 相等组仅适合项目已经确认的语义；v1 不预设事务守恒方程，也不把计数相等视为数据值正确。

阈值、种子和计数定义随验证包进入 G3 审核。新增、修改或删除合同会改变验证摘要；不得通过移除文件或放宽阈值让既有失败变为通过。正式回归仍只由编排者执行，tb-engineer 的黑盒边界不变。

## 桩检查与缓存

`--stub` 校验合同结构并使用显式种子矩阵，但不强制真实 DUT 活动指标，仍按桩模式的编译、启动和终止规则判断。桩 PASS 只能解释为平台自检，不是实际 DUT 检查通过。

报告绑定合同与运行输入摘要；启用模式还绑定计划文档和数据描述。文本输入摘要统一 CRLF/LF，避免远端上传换行转换导致正常结果被误判过期；档案中的文件摘要仍按保存的原始字节计算。新增、修改、删除合同会使相关缓存失效。无合同的旧报告保持原来的兼容语义，不将旧结果自动升级为严格证据模式。

## 运行记录

启用后每次执行创建独立的 `reports/evidence/<run_id>/`，保存编译输出、各 test/seed 日志、结果和 SHA-256 清单。编译或测试失败也留存记录，重跑创建新的目录。现有 `reports/regress.json`、桩结果及构建日志入口保留，方便原有流程继续使用。

记录与选定种子矩阵绑定，缺少运行、额外运行或重复运行不能被当作完整通过。局部运行应明确报告为局部检查；不能拼接不同计划版本的结果。历史尝试保留供复核，不默认用最新 PASS 删除先前失败。

远程执行会采集这些小型证据文件；FSDB、大型二进制和覆盖数据库不复制进该档案，仍走原有路径和保留策略。此档案不是完整编译工件存储，也不是通用历史结果聚合器。直接运行入口的基础设施异常或在进入报告阶段前被强制终止，不保证生成完整档案，应按失败/证据不完整处理。

## 验证与边界

项目接入时至少验证：零观测/零检查失败、错误值失败、未完成事务失败、缺失或重复指标失败、种子/用例不匹配失败、正常样例通过。进一步用断开 monitor、错误数据或遗漏响应验证检查器确实敏感；代码解析器测试不能代替真实 DUT 实验。

日志摘要用于检测文件变化，不等于可信签名或操作系统隔离；同权限的进程仍可能伪造指标。活动非零不代表覆盖闭合；既有 COVER 与覆盖目标也不能由计数替代。本实现不包含本地第三方 skill 的源码、legacy 平台模板或内部规范，不改变 UVM 库标准及远程认证方式。
